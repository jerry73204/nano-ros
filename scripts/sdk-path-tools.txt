# Provisioned tools that MUST be reachable by BARE NAME — issue 0663.
#
# `nros setup --tool <x>` installs into the SDK store
# (`~/.nros/sdk/<tool>/<version>/bin`). Nothing there is on `PATH` by default,
# and that is deliberate: the test harness resolves qemu, zenohd and friends
# through an explicit `build/<tool>` prefix so a stray store copy cannot shadow
# the one a lane pinned.
#
# But some tools are invoked by BARE NAME by something we do not control — an
# RTOS `make`, a cmake `find_program`, a build script — and for those, "in the
# store" and "not on PATH" means provisioning succeeded and the step still
# skipped. That has now happened three times, each found separately:
#
#   genromfs   NuttX's rv-virt ROMFS bake calls it (Phase 194.3c)
#   espflash   `just esp32 build-qemu` packs its flash image by bare name
#              (issue 0486) — provisioned, and the pack step still skipped
#   idlc       the CycloneDDS IDL compiler. `nros setup --tool cyclonedds`
#              installs it (the index builds with BUILD_IDLC=ON), and every
#              Cyclone fixture lane still skipped with "idlc not found",
#              telling the user to run the DEV recipe instead (issue 0663)
#
# The list lived as a hand-written `[ -x … ] || [ -x … ]` chain in BOTH
# `activate.sh` and `activate.fish`, and had already drifted: `espflash` was in
# the bash one and not the fish one, so the same host behaved differently in
# two shells. One file, read by both.
#
# RETIRED ENTRIES
#
#   zenohd   removed 2026-08-18 (issue 0653). phase-362 / RFC-0075 replaced the
#            vendored router with ROS's `rmw_zenoh_cpp/rmw_zenohd`, and the SDK
#            index entry went with it — but this line stayed, so any host that
#            had ever provisioned it kept putting `~/.nros/sdk/zenohd/<v>/bin`
#            on PATH forever. That is not merely dead weight: it is a RETIRED
#            router shadowing the paired one. Measured on the machine that found
#            it — `command -v zenohd` gave the store's 1.7.2 while ROS shipped
#            zenoh-c 1.8.0, 801 MB of it, still first on PATH months after the
#            retirement. The router is also never invoked by bare name (the
#            resolvers take an absolute path), so it never belonged on this list
#            once it came from ROS.
#
# Removing a name here does NOT delete the store directory; nothing does, since
# the store is documented to accumulate (issue 0500). `just doctor` reports a
# retired entry that is still installed so it can be removed deliberately.
#
# Format: one bare tool name per line; `#` comments and blanks ignored.
# A cross-gcc needs no entry — both shells detect `*-gcc` in the dir directly.

genromfs
sccache
espflash
idlc
# make + ninja — the two halves of the Phase 176 unified jobserver, and both
# invoked by BARE NAME by things we do not control: cmake generators and RTOS
# kernel makefiles call `make`/`gmake`, every cmake configure emits for `ninja`.
#
# They moved here from two hand-written PATH blocks in activate.sh pointing at
# `third-party/{make,ninja}/`, which `just workspace install-{make,ninja}`
# filled. Those recipes are gone: provisioning is `nros setup --tool {make,ninja}`
# like every other tool, so the version pin lives in the index instead of a
# `just` variable that could drift from it.
#
# Listing `make` is enough to put its bin dir on PATH — the `gmake` alias sits
# beside it in the same directory, and this list gates the DIRECTORY.
make
ninja

# The cargo tools — phase-422 W2 (second half).
#
# `cargo nextest` is cargo finding `cargo-nextest` ON PATH: a cargo subcommand
# is invoked by bare name by cargo itself, which is exactly what this list is
# for. Before they were indexed these sat in `~/.cargo/bin`, which rustup puts
# on PATH; installed into the versioned store they need this line instead, and
# without it `just test` would report nextest missing on a host that had just
# provisioned it.
#
# `rustfilt` is here for the same reason one level over: `just mem-report` and
# the profiling scripts pipe through it by bare name.
cargo-nextest
cargo-llvm-cov
cargo-asm
rustfilt
