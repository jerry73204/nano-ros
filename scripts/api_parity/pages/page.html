How to read this. Every row is one item in the recorded ROS 2 surface, one item in ours, or a correlated pair. The seven states are decisions recorded in the parity ledger, not guesses: same means the signature correlates exactly; re-shaped means we keep the capability under a changed shape, with the platform constraint named; renamed means the same thing under a different name; re-mapped means one upstream item answers to several of ours or several to one — those rows carry an explicit provides arrow, hand-authored, never inferred; rejected means we declined it on the record; not implemented is an open gap; ours only has no upstream counterpart.

Two surfaces, on one page. The C++ rows measure what a PORTED FILE reaches — rclcpp_compat.hpp included, because #include <rclcpp/rclcpp.hpp> resolves to it. A row marked via rclcpp_compat.hpp is one the shim alone answers; a row marked native API is one the native nros:: headers answer differently, and that second label is the number this page used to report on its own (issue 1020).

Disposition is a second axis and answers a different question from the state: not what we did, but what a porting user GETS — adopt, adopt · bounded (weaker inside a documented envelope), refuses loudly (the name exists and fails to COMPILE, with the alternative named), absent. Rows without one have not been classified yet; that pass is phase-417 W-M2 (RFC-0087).

A group states its reason once when every member shares one verdict, rather than repeating it across the members. Where a reason cites a symbol in backticks, that symbol is meant to exist — fifteen currently do not, which is issue 1012.
