# Issue 0050 — audited weak-symbol allowlist (single source of truth).
#
# Every owned C/C++/asm file that defines weak symbols (`__attribute__((weak))`
# / `.weak`) is listed here with its expected weak-decl count + classification.
# Both gates read this file:
#   - scripts/check-weak-symbols.sh  (fast source-level scan, in `just check`)
#   - nros-tests/tests/weak_symbol_audit.rs (the same scan as a Rust test)
# Drift (a new weak site, or a count change in a listed file) fails both —
# forcing a re-audit + an update here.
#
# Format:  <expected-count> <repo-relative-path>   # classification
# (vendored zenoh-pico / mbedtls / third-party are excluded from the scan.)
# Classification: override-default = a strong def is guaranteed elsewhere
# (board / app / cmake stub); optional-hook = the weak no-op IS the intended
# fallback.
#
# SECOND AXIS (phase-386): `body:<kind>` answers a DIFFERENT question —
# if nobody overrides it, is the weak body CORRECT?  The two are independent:
# a layered platform default is `optional-hook` AND correct, while a stub that
# returns a success value is `optional-hook` AND a live bug.
#
#   body:correct         the weak body is a valid runtime state; nothing is
#                        missing when no override exists (a no-op log sink,
#                        RFC-0077's panic default).
#   body:reports-failure it cannot do the job and says so in a form its CALLER
#                        understands — the API's error sentinel, a set errno,
#                        a printed fail-loud message.
#   body:self-enforcing  misuse faults immediately (`stdin = NULL`). Louder
#                        than any diagnostic, and DO NOT "fix" it: a non-NULL
#                        placeholder turns a hard fault into a silent misread.
#
# There is deliberately no `body:silent-wrong`. That state is the bug this axis
# exists to prevent, and phase-386 W2 removed the two that had it (zpico
# send/read returned 0, a SUCCESS value, where callers test SIZE_MAX; the
# ThreadX libc stubs returned -1 with a STALE errno). A row that would need it
# should be fixed, not labelled.
#
# Image gate (scripts/check-weak-symbols-image.sh) SSoT: an `[img: <sym> <sym> …]`
# token names the exact symbols whose strong override must win in a FINAL linked
# image. That gate cross-checks its coverage map against this set: every covered
# symbol must be declared here, and a declared symbol with no coverage row yet is
# reported (not silently dropped). Both source-level gates take only the text
# before `#`, so the token is invisible to them.
#
# `[img:]` is INDEPENDENT of the override-default/optional-hook classification
# (phase-386 W3a). This paragraph used to say an [img:] token belongs to "an
# override-default line" and that "optional-hook lines carry no token", which
# read as a rule and is not one: the gate parses [img:] from ANY row starting
# with a digit and never inspects the classification. Verified by relabelling a
# row and re-running — coverage unchanged.
#
# The distinction that sentence obscured, and the reason it matters:
#   override-default / optional-hook  is a strong def GUARANTEED to exist?
#   [img: …]                          which symbols do we EXPECT specific
#                                     images to override, and want checked?
# Those are different questions. A row can legitimately be an optional-hook —
# no override guaranteed anywhere — and still carry [img:] because the images we
# DO ship are expected to override it. `network_glue.c` is exactly that case
# (issue 0769): its weak returns -1 meaning "no Ethernet", a supported shipped
# state, while LAN9118 MPS2 images are expected to override and worth gating.
#
# The cost of the old wording was real: it made a correct relabel look like it
# would silently narrow coverage, so the relabel was declined and the row still
# carries a classification its own issue calls wrong.
